📋 Project Overview

Project Description

A real-time online banking fraud detection system built with microservices architecture. The system monitors transactions in real-time, applies rule-based and machine learning-based fraud detection, and makes automatic decisions (approve/OTP/block) based on risk scores.

Key Features

  • Real-time transaction monitoring
  • Rule-based fraud detection with configurable rules
  • Machine learning integration (Isolation Forest)
  • Risk-based authentication (OTP challenge)
  • Comprehensive audit logging
  • High availability with circuit breakers
  • Event-driven architecture with Kafka
  • JWT-based authentication

🔄 Transaction & Fraud Detection Flows

User Login Flow

User ↓ Login Page (React) ↓ Enter credentials API Gateway (8080) ↓ Route: /auth/** Auth Service (8081) ├─ Validate username/password ├─ Hash & compare └─ Generate JWT token ↓ Return token Frontend ├─ Save to localStorage ├─ Set isAuthenticated = true └─ Redirect to Dashboard

Transaction & Fraud Detection Flow

User submits transaction ↓ Frontend (DashboardPage) ├─ Amount ├─ Merchant └─ Description ↓ POST /transaction/transfer API Gateway (8080) ├─ Validate token ├─ Route to /transaction/** └─ Check Circuit Breaker Transaction Service (8082) ├─ Validate data ├─ Generate transaction_id ├─ Store in database └─ Publish to Kafka: transaction-events ↓ Fraud Engine (8083) [Async Consumer] ├─ Receive Kafka event ├─ Calculate risk score: │ ├─ Large amount? +40 │ ├─ New device? +30 │ └─ Foreign location? +50 │ ├─ Decision: │ ├─ score ≤ 40 → APPROVED │ ├─ score ≤ 70 → OTP_REQUIRED │ └─ score > 70 → BLOCKED │ └─ Publish: fraud-alerts ↓ Branches ├─→ APPROVED │ └─→ Display: ✓ Transaction Approved │ ├─→ OTP_REQUIRED │ ├─→ Notification Service sends OTP │ ├─→ User enters OTP in frontend │ └─→ Auth Service verifies │ └─→ BLOCKED └─→ Display: ✗ Transaction Blocked ↓ Audit Service (8086) ├─ Log: TRANSACTION_CREATED ├─ Log: FRAUD_EVALUATED └─ Log: FRAUD_BLOCKED/APPROVED

Risk Scoring Algorithm

score = 0 Check 1: Amount ├─ if (amount > $5000) │ score += 40 └─ else score += 0 Check 2: Device ├─ Query User Service ├─ if (new_device_detected) │ score += 30 └─ else score += 0 Check 3: Location ├─ Get user_location ├─ if (foreign_country) │ score += 50 └─ else score += 0 Decision Matrix: ├─ score: 0-40 → ✓ APPROVED ├─ score: 41-70 → ⚠ OTP_VERIFICATION └─ score: 71-120 → ✗ BLOCKED

🗄️ Database Schema

Auth Service Database

users table: - id (BIGSERIAL PK) - username (VARCHAR UNIQUE) - password (VARCHAR) - email (VARCHAR UNIQUE) - is_active (BOOLEAN) - created_at (TIMESTAMP) - updated_at (TIMESTAMP) sessions table: - id (BIGSERIAL PK) - user_id (BIGINT FK) - token (VARCHAR UNIQUE) - expires_at (TIMESTAMP) - created_at (TIMESTAMP) Indexes: user_id, token, expires_at

Fraud Engine Database

fraud_rules table: - id, rule_name, rule_type, threshold, is_active fraud_alerts table: - id, transaction_id, fraud_score, risk_level, status, created_at fraud_patterns table: - id, user_id, pattern_type, detected_value, detected_at Indexes: transaction_id, status, user_id, created_at DESC

Audit Service Database

audit_logs table: - id (BIGSERIAL PK) - event_type (VARCHAR IDX) - description (VARCHAR) - user_id (VARCHAR IDX) - transaction_id (VARCHAR IDX) - request_id (VARCHAR IDX) - severity (VARCHAR IDX) - created_at (TIMESTAMP IDX DESC) Indexes: event_type, user_id, transaction_id, severity, created_at DESC Query Performance: All major queries use indexes

🔒 Security Architecture

🔐 Authentication & Authorization
  • JWT token-based authentication
  • OTP for high-risk transactions (41-70 score)
  • Token expiration: Configurable (default 1 hour)
  • Refresh token mechanism
  • Password hashing with BCrypt
🛡️ Circuit Breaker Pattern
  • Enabled on all 6 service routes
  • Failure threshold: 50%
  • Sliding window: 20 calls
  • Open state timeout: 10 seconds
  • Auto recovery mechanism
  • Fallback response on failure
🔗 HTTPS & Transport Security
  • Frontend ↔ API Gateway: HTTPS only
  • Inter-service: Private Docker network
  • Bearer token in Authorization header
  • Rate limiting ready for deployment
📝 Audit & Compliance
  • All actions logged with timestamps
  • User ID tracking
  • Transaction ID tracing
  • Severity levels: INFO, WARNING, ERROR, CRITICAL
  • Queryable audit trail
  • Retention ready (can implement TTL)
